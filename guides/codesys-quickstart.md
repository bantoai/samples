# CODESYS のはじめかた：自己保持回路を動かすまで

CODESYS を初めて触る人向けに、PC だけでラダーを動かすまでの最小限の手順をまとめました。
「盤とAI」の記事で CODESYS を使うときの共通の前提です。

- A. 自己保持回路を手で描いて、ビルドし、強制入力で動きを確かめる
- B. PLCopen XML（記事のサンプルなど）を取り込んで動かす

## CODESYS とは

CODESYS は、IEC 61131-3（PLC のプログラム言語の国際規格）に沿った PLC の開発ソフトです。特定のメーカーの PLC 専用ではなく、多くのメーカーの機器で使われています。
開発ソフトは無料で、PC の中で動くソフト PLC（CODESYS Control Win V3）も付いているので、実機がなくてもラダーを書いて動かせます。

## 確かめた環境

| 項目 | 内容 |
|---|---|
| CODESYS | V3.5 SP22 Patch 4（64bit、日本語表示） |
| ソフト PLC | CODESYS Control Win V3 x64（ライセンスなしのデモモード） |

- インストーラは公式の CODESYS Store から入手します（アカウント登録が要ります）
- デモモードのソフト PLC は **2時間で止まります**。止まったら起動し直せば続けて使えます
- 他のバージョンでは、メニューの名前や場所が違うことがあります

## A. 自己保持回路を手で描いて動かす

### A-0. 作る回路

起動PB（押しボタン）を押すと出力が ON になり、手を離しても ON のまま（自己保持）、停止PB で OFF になる回路です。

```
 |   bStart        bStop           bMotor  |
 |----| |----+-----|/|--------------( )-----|
 |           |                             |
 |   bMotor  |                             |
 |----| |----+                             |
```

| 変数 | 型 | 役割 |
|---|---|---|
| bStart | BOOL | 起動PB（a接点：押すと ON） |
| bStop | BOOL | 停止PB（b接点：押すと OFF） |
| bMotor | BOOL | 出力のコイル／自己保持の接点 |

### A-1. プロジェクトを作る

1. 「ファイル → 新規プロジェクト」
2. カテゴリ「プロジェクト」→ テンプレート「標準プロジェクト」
3. 名前（例：`SelfHold`）と保存場所を決めて「OK」
4. 「標準プロジェクト」の画面で次を選んで「OK」
   - デバイス：`CODESYS Control Win V3 x64`
   - PLC_PRG の言語：`ラダーロジックダイアグラム (LD)`
5. デバイスツリーに `SelfHold → Device → PLC Logic → Application → PLC_PRG (PRG)` ができる

### A-2. タスクへの登録を確かめる

1. ツリーの `タスク構成 → MainTask` をダブルクリック
2. 呼び出しの一覧に `PLC_PRG` があるか見る
3. なければ「呼び出しの追加」で `PLC_PRG` を選ぶ

> ツリーで PRG が灰色のときは、どこからも呼ばれておらずビルドされません。
> 自分で POU（プログラムの単位）を足したときも、MainTask への登録を忘れないようにします。

### A-3. エディタを開いて変数を宣言する

1. ツリーの `PLC_PRG (PRG)` をダブルクリック（上半分が宣言部、下半分が実装部）
2. 宣言部の `VAR` ～ `END_VAR` の間に書く

```
PROGRAM PLC_PRG
VAR
    bStart : BOOL;   (* 起動PB *)
    bStop  : BOOL;   (* 停止PB *)
    bMotor : BOOL;   (* 出力 *)
END_VAR
```

行末の `;` を忘れるとビルドでエラーになります。

### A-4. ラダーを描く

- 実装部を一度クリックしておく（ツールボックスの中身は、選んでいるエディタに合わせて変わる）
- ツールボックスがなければ「表示 → ツールボックス」。「ラダー要素」の 接点・否定接点・並列接点・コイル を使う
- 部品をドラッグすると出るグレーの◇の印にドロップして置く

1. 「接点」をネットワーク1の線の上に、「コイル」をその右に置く
2. 接点の `???` に `bStart`、コイルの `???` に `bMotor` を入れる
3. 「否定接点」（b接点）を bStart とコイルの間に置き、`bStop` を入れる
4. 「並列接点」を bStart の**下側**に置き、`bMotor` を入れる

`???` を入力するとき `F2` を押すと、宣言した変数から選べます。

### A-5. ビルドする

「ビルド → ビルド」（F11）。メッセージ欄が「0 エラー」になれば OK です。

### A-6. ソフト PLC を起動してつなぐ

1. タスクトレイの CODESYS Control Win SysTray のアイコンを右クリック →「Start PLC」
2. ツリーの `Device` をダブルクリック →「通信設定」タブ →「ネットワークをスキャン」
3. 自分の PC を選んで「OK」（ランプが緑になればつながっています）

初めてつなぐと「デバイスユーザーの追加」が出ます。これは Windows のアカウントではなく、**ソフト PLC 専用のユーザー**です。名前とパスワードは自由に決めてよく、次からのログインで使います（忘れないように控えておきます）。

### A-7. ログインして実行する

1. 「オンライン → ログイン」（Alt+F8）→ ダウンロードの確認に「はい」
2. **「デバッグ → 開始」（F5）**
3. ツリーの `Application` が「実行中」になっていることを確かめる

> ログインしただけでは PLC は**止まっています**。止まっていても強制した接点の値は表示されますが、演算されないのでコイルは変わりません。

### A-8. 強制入力で動きを確かめる

1. 「ウォッチ 1」の「式」の欄に `bStart`・`bStop`・`bMotor` を足す（オンライン中は「値」の列に今の値が出る）
2. 「準備値」の欄をクリックして値を決め、F7 で強制する

BOOL の準備値は、**1回クリックするごと**に `TRUE → FALSE → 空欄` と変わります。ダブルクリックすると2回変わって元に戻ったように見えるので注意してください。

| 手順 | 操作 | 期待する結果 |
|---|---|---|
| 1 | bStart を `TRUE` → F7 | bMotor が TRUE |
| 2 | bStart を `FALSE` → F7 | bMotor は TRUE のまま（自己保持） |
| 3 | bStop を `TRUE` → F7 | bMotor が FALSE |
| 4 | bStop を `FALSE` → F7 | bMotor は FALSE のまま |

- 強制している変数には赤い「F」の印が付く
- オンラインのラダーでは、TRUE の接点・コイル・線が青く表示される

### A-9. 終わる

1. 「デバッグ → 強制解除」（Alt+F7）
2. 「オンライン → ログアウト」（Ctrl+F8）
3. タスクトレイのアイコンから「Stop PLC」

## B. PLCopen XML を取り込んで動かす

記事のサンプルのように、ラダーを PLCopen XML（ラダーを XML で表したもの）で受け取ったときの手順です。
例として、記事「生成AIにラダー回路を書かせてみた」の自己保持のサンプルを使います。

- [sample_selfhold.xml](https://github.com/bantoai/samples/blob/ai-ladder-generation-codesys-v1/articles/ai-ladder-generation-codesys/xml/sample_selfhold.xml)（ラダー）
- [GVL_IO.st](https://github.com/bantoai/samples/blob/ai-ladder-generation-codesys-v1/articles/ai-ladder-generation-codesys/gvl/GVL_IO.st)（ラダーが使う変数）

### B-1. 先に変数（GVL）を作る

サンプルのラダーは、PLC_PRG の中ではなく、グローバル変数リスト（GVL：どのプログラムからも使える変数の一覧）`GVL_IO` の変数を使います。取り込む前に作っておきます。

1. A-1 と同じ手順でプロジェクトを作る
2. ツリーの `Application` を右クリック →「オブジェクトの追加 → グローバル変数リスト」、名前を `GVL_IO` にする
3. 開いた `GVL_IO` の中身を、`GVL_IO.st` の中身に置き換える

### B-2. XML を取り込む

1. ツリーで **`Application` を選んだ状態にする**
2. 「プロジェクト → PLCopenXML のインポート」で XML を選ぶ
3. 最初からある `PLC_PRG` とぶつかると聞かれるので、置き換える
4. `PLC_PRG` をダブルクリックして、ラダーで表示されるかを見る
5. ビルド（F11）して「0 エラー」を確かめる

このあとは A-2（タスクへの登録）と、A-6〜A-9 と同じです。ウォッチには `GVL_IO.xMixOnPB` のように、GVL の名前を付けて足します。

## うまくいかないとき

| 起きたこと | 原因 | 直し方 |
|---|---|---|
| ツールボックスに「ラダー要素」が出ない | LD のエディタを開いていない／選んでいない | PRG をダブルクリックし、実装部をクリック |
| ツリーで PRG が灰色 | MainTask に登録されていない | MainTask で「呼び出しの追加」 |
| ウォッチに変数を足しても値が出ない | GVL の変数を名前だけで足した／変数を見つけられていない | `GVL名.変数名` で足す。F2 の入力アシスタントから選び直す |
| 「準備値」を変えられない | オフライン／ダブルクリックしている | ログインする。BOOL は1回ずつクリック |
| 条件はそろって通電表示も出ているのにコイルが ON しない | PLC が止まっている | 「デバッグ → 開始」（F5） |
| 同上（実行中なのに） | 同じ変数に2か所で書き込んでいる（二重コイル） | クロスリファレンスで書き込む所を探し、1か所にする |
| 同上（実行中・二重コイルなし） | 出力の変数そのものを強制している | 強制解除（Alt+F7）して、入力だけ強制し直す |
| ネットワークのスキャンで PC が見つからない | ソフト PLC を起動していない／ファイアウォール | 「Start PLC」とファイアウォールの設定を確かめる |
| 「現在選択されている場所でインポートすることができるエクスポートファイルにはオブジェクトがありません」 | `Application` を選ばずに取り込んだ | `Application` を選んでから取り込む |
| 取り込んだあとのビルドで、変数が見つからないエラー | GVL を作っていない／名前が違う | B-1 の `GVL_IO` を先に作る |
| デバイスユーザーのパスワードを忘れた | — | CODESYS の公式のヘルプで、ランタイムのユーザー管理を初期化する手順を確かめる |

## よく使うキー

| 操作 | キー |
|---|---|
| ビルド | F11 |
| ログイン／ログアウト | Alt+F8 ／ Ctrl+F8 |
| 実行開始 | F5 |
| 値の強制／強制解除 | F7 ／ Alt+F7 |
| 値の書き込み（1回だけ） | Ctrl+F7 |
| 入力アシスタント | F2 |
